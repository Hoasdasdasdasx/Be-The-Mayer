# UI 개편 검증 기록

## 변경 파일

- `client/index.template.html`: 화면 구조와 규칙·설정·초대 모달.
- `scripts/build-client.cjs`, `public/index.html`: 스타일과 UI 코드를 포함한 단일 HTML 생성 및 최신 상태 검사.
- `public/styles.css`: 카드 프레임, 손패, 낮·밤 테마, 반응형, 애니메이션과 접근성 스타일.
- `public/ui.js`: 카드·후보 컴포넌트, SVG 일러스트, 실행 불가 사유 표시.
- `public/app.js`: 상태 렌더링, 카드 선택·대상·확인, 중복 요청 잠금, 재접속.
- `server.js`: 기존 연결 해제 자동 진행 호출 보완.
- `package.json`, `package-lock.json`, `.gitignore`: 검증 명령, 개발 테스트 의존성, 생성물 제외.
- `playwright.config.cjs`, `tests/server-harness.cjs`, `tests/rules.test.cjs`, `tests/browser/game.spec.cjs`, `tests/browser/protocol.spec.cjs`, `tests/browser/portable.spec.cjs`: 규칙·브라우저·실제 통신·단독 HTML 검증.
- `README.md`, `docs/ui-contract.md`, `docs/ui-validation.md`: 실행, 기존 계약, 검증 및 제한 기록.

## 보존 범위

18종 카드 정의, 구매 비용, 효과, 장소 정원, 자원 합산, 10턴 종료 및 공동 승리, 이벤트 이름과 페이로드는 보존했다. `public/ui.js`는 서버의 카드 데이터를 표시하며 별도 효과 목록을 갖지 않는다.

서버 변경은 기존 연결 해제 자동 진행 함수를 단계 전환 이벤트 뒤에도 호출하는 5줄뿐이다. 기존 버전에서는 장소 선택 중 먼저 끊긴 후보가 다음 행동 순서의 첫 번째가 되면 자동 건너뛰기가 호출되지 않았다. 이 조건을 회귀 테스트로 재현하고 수정했다. 새 게임 규칙은 추가하지 않았다.

진행 중 UI의 방 나가기는 소켓 연결을 끊어 같은 자동 진행 경로를 사용한다. 대기실에서는 기존 `leaveRoom` 이벤트로 후보를 제거한다.

## 수행한 검증

- Node.js 24, 시스템 Chromium 154에서 실행. Node.js 20 이상 요구사항은 유지.
- `npm run check`: 서버와 두 클라이언트 모듈 문법 검사.
- `npm run build`: CSS와 모듈을 단일 HTML에 포함. `check`는 생성물이 소스와 일치하는지도 검사한다.
- `npm test`: 24개 테스트. 실제 서버 파일을 VM에서 실행하고 네트워크 계층만 대체.
  - 6인·10인 방의 모든 장소 정원과 회전 우선권, 비공개 장소 선택.
  - 최소 시작 인원, 자원 부족, 비용 차감, 손패 4장 한도, 비공개 손패.
  - 18종 카드 각각의 효과와 중복 사용 방지.
  - 사용 시점, 밀실 거래의 다음 턴 제한, 강탈 보호, 시청 봉쇄 대체 자원.
  - 10턴 낮·밤 진행, 구매·사용 건너뛰기, 공동 승리, 연결 해제·재접속.
- Playwright 실제 서버 검증:
  - 독립 브라우저 컨텍스트 2개로 6인 방 생성, 초대 링크 참가, 시작, 비공개 선택, 재접속 후 10턴을 UI 버튼으로 완료. 공동 당선 및 각 20점 확인.
  - 10인 모드 방에서 시장 5장, 두 참가자의 상가·술집·시청 자원 획득 및 구매 부족 표시.
  - 실제 Socket.IO 클라이언트 2개로 자원을 모아 카드 구매·비용 차감·사용 및 상대 손패 비공개 확인.
- 결정적 브라우저 검증 (네트워크 응답만 대체, 카드 정의와 결과 상태는 실제 서버 VM에서 생성):
  - 18종 카드 표시, 비용, 대상 후보·자원·시장 선택, 요청 중 중복 입력 잠금, 서버 확인 후 카드 제거.
  - 관련 없는 상태 변경 후 카드와 대상 유지, 구매 전 확인, 오류 후 복구, 서버 확인 후 손패 추가, 손패 한도와 다음 턴 제한.
  - 단독·공동 당선, 새 선거 시작 화면.
  - 1920×1080, 1366×768, 390×844에서 가로 넘침·긴 설명·호버 가림·키보드·접이식 패널·모션 감소.

PC·모바일 모두 세로 문서 스크롤을 사용한다. 작은 화면에서는 카드 그리드와 접이식 후보 패널로 조작하며, 로그·모달이 아닌 게임판 자체에는 중첩 스크롤을 만들지 않았다.

HTML 단독 미리보기 회귀 검증에서는 모든 외부 파일 요청을 차단한 뒤 스타일, SVG, 규칙·설정, 서버 부재 안내, 방 생성·참가 비활성화를 확인한다. JavaScript를 비활성화한 브라우저에서도 스타일과 안내가 유지되는지 별도로 확인한다.

## 남은 제한

- Firefox, Safari, 실제 모바일 기기, 6명·10명 동시 실사용 부하 테스트는 수행하지 않았다. 정원 규칙은 VM에서 각각 6명·10명으로 검증했다.
- 모든 카드 효과의 실시간 네트워크 조합을 전수 플레이한 것은 아니다. 18종은 서버 VM과 결정적 브라우저 테스트로 검증했고, 실제 네트워크의 구매·사용 경로를 별도로 확인했다.
- 기존 구조대로 방은 메모리에만 저장되며 서버 재시작 시 소멸한다. 공개 배포·계정·영구 저장은 이번 UI 개편 범위에 포함되지 않는다.
- 외부 번들러 없이 `npm run build`로 배포할 HTML을 생성한다. 실제 페이지와 소켓 테스트로 실행을 검증한다.
